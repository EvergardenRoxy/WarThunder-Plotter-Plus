# 游戏录像

除了 8111 实时采集，程序还能读取游戏自己的 `.wrpl` 录像，补上 8111 拿不到的信息：全体玩家的名字、战队、队伍、得分和击杀数，玩家击杀记录（谁用什么载具击毁了谁），以及聊天。录像还能还原飞机（空战）或地面载具（陆战）的轨迹，给没有 8111 记录的比赛生成回放。

| 来源 | 位置 | 覆盖范围 |
| :--- | :--- | :--- |
| 本地录像 | 游戏目录下的 `Replays\#日期 时间.wrpl` | 从开局到自己离开战局 |
| 服务器录像 | 录像 CDN，按场次号下载，分成多段 | 整场战局；含最终战绩和比赛结果 |

本地录像和服务器录像的场次号相同，导入后归到同一场比赛；战报优先显示服务器录像。

## 使用

历史战局页顶部展开「导入游戏录像」：

- **本地录像文件夹**：填游戏的 `Replays` 目录，点「导入新录像」。这一步只读录像的文件头和结尾的战绩，一百份录像不到一秒；已经导入过的场次会跳过。第一次打开某场比赛时才完整解析击杀、聊天和轨迹（每场约 2–6 秒，个别长局十几秒），之后直接打开。程序升级了录像解析时，打开比赛会按新版本重新解析；游戏正在写入或损坏的文件导入失败时，只在结果里列出，不影响其它文件。完整解析失败（文件已删除、移动或格式认不出）时，比赛照常打开，战报顶部写明失败原因，同一解析版本不再重试。
- **服务器录像**：填 16 位十六进制场次号（本地录像的场次号可在战报接口里看到）或末尾带场次号的链接，点「下载并导入」。分段保存在数据目录的 `replays\<场次号>\`。服务器只保留一段时间，过期后返回「没有这场录像」。

有录像的比赛在列表里带「录像」标记，比赛页右上角出现「战报」按钮。

命令行也可以导入，会直接完整解析（重复导入会整体替换该场录像的数据）：

```powershell
.\.venv\Scripts\python -m wt_plotter import-replay "D:\WarThunder\Replays"
.\.venv\Scripts\python -m wt_plotter download-replay 72c412c1002817ae
```

## 与已有比赛的关联

1. 同一场次号已经导入过 → 用同一场比赛。
2. 否则找开始时间与录像开始时间相差 120 秒内、尚未关联其它场次的比赛（8111 记录）。
3. 都没有 → 新建一场已结束的比赛，地图按关卡名对应内置地图（陆战用 `<关卡>_tankmap`，空战用 `<关卡>_map` 或关卡名本身）。

录像比本地记录更长时（服务器录像），比赛结束时间会推后到录像结束。

## 录像轨迹

录像会还原单位轨迹，写成和 8111 采集相同的 tick 与位置，查看器直接回放：录像者是「自己」，同一真实小队是「小队」，其余按队伍分为友军和敌军；击杀记录同时写进战斗播报。

- **空战**（战斗类别不是 `air_ground_*`）：还原每架飞机（含录像者自己和 AI）的轨迹（类型 2）。
- **陆战**（`air_ground_*`）：还原全部地面单位（地面同步消息）和玩家开的飞机（类型 2）的轨迹。各单位的采样时刻不同，按 1 秒一帧插值，相邻采样间隔超过 15 秒的空档不补。地面单位统一画成中坦图标。没有归属、整命都不动（位移不到 30 米）的单位是地图上的静态物体，不画。录像还原的陆战回放在地面图上也画飞机（8111 采集的陆战不画）。
- 只给**没有 8111 轨迹**的比赛写入；已有 8111 记录的比赛保持原样。录像写入的轨迹可以被服务器录像替换（完整战局），反过来不会。
- 服务器录像不知道是谁录的，沿用同一场本地录像记下的录像者；都没有时把队伍 1 当作友军。
- 位置点带上玩家名和机型（查看器里鼠标悬停可见）：机型取这一命出手时报出的；没出过手但这名玩家整场只知道一种载具（含服务器结果块的出战载具）时用它；AI 没有名字。
- 被击毁的单位在击毁时截断：空战里坠落中的残骸、陆战里停在原地的残骸都不画；同一单位号之后断档再出现或离开残骸位置，算复活后的新一命。
- **地图范围**：世界坐标换算到小地图需要地图的世界坐标范围。8111 的 `map_info.json` 会给出（`map_min` / `map_max`），采集时按地图记下，存在 `map_bounds` 表里。某张地图采集过一次以后，同一地图的录像就能画在底图上；还没采集过的，比赛不显示底图，轨迹按自身范围铺满画布。采集过后用命令行重新导入即可补上底图。
- 换算方向：地图 x 随世界 x 向右增大，地图 y 随世界 z 增大而向上（图片 y 向下）。已用 3 场空战、10 场陆战的 8111 记录核对过。

已知限制：

- 单位号会复用，归属按「命」判断（见下文）。不属于玩家的飞机（AI）按队伍成段编号：被玩家击落的算击杀者的对方，同一段同队，没有证据的段取紧邻段的对方。仍不知道队伍的单位（多是陆战里没出过手的复活载具）按起点归到最近的已知队伍。对照 8111 颜色，能对上的位置中关系一致的：陆战约 96%–99%，空战约 92%–95%。
- 录像者自己的坦克只在能确定归属的那几命标成「自己」。

## 文件格式

`.wrpl` 由文件头、设置 BLK、zstd 压缩的数据包流和结果 BLK 组成。实现在 `wt_plotter/replay/`，格式要点如下（版本 101421 实测）。

| 偏移 | 内容 |
| :--- | :--- |
| 0 | 魔数 `E5 AC 00 10` |
| 8 / 136 / 396 | 关卡、任务文件、任务名（定长 C 字符串） |
| 684 | 结果 BLK 偏移（u32，0 表示没有） |
| 732 | 场次号（u64） |
| 740 | 服务器录像分段号；742 为 `0x5A` 表示服务器录像 |
| 748 | 设置 BLK 长度（u16） |
| 908 | 开始时间（Unix 秒） |
| 968 | 战斗类别，如 `air_ground_Dom`（陆战）、`base_dom`（空战） |
| 1234 | 设置 BLK；其后到结果 BLK 之前是 zstd 包流 |

- **BLK**：首字节 `0x01` 的 FAT 格式：名字表、参数数据区、参数表（每项 u32 名字号与类型、u32 值或偏移）、块表（名字号、参数数、子块数、首个子块号）。
- **包流**：每个包是长度前缀加内容。前缀高位决定字节数（`10` 一字节、`01` 两字节、`001` 三字节、`0001` 四字节、`0000` 后跟 u32）。内容首字节是类型；不带 `0x10` 标记时后跟 u32 时间戳，单位为 1/256 毫秒，带标记时沿用上一个时间戳。
- **类型 3**：聊天，依次为标记字节、发送者、正文（各带一字节长度）、频道。
- **类型 4**：游戏消息，前 5 字节是签名（`00 02 58` + 消息 id 的低字节 + `F0`/`F1`）。多数消息的内容是**按字段序列化**的：u16 尺寸表字节偏移、7 位变长整数的字段位掩码、各字段数据（高位在前的位流）、尺寸表（每个字段 3 位头：1/8/16/32/64/96/128 位，0 表示后跟变长整数位数）。单位号是 u16 的低 11 位，`7FF` 表示无。
  - `00 02 58 58` 击杀：字段 1 击杀者槽位（u32，`FFFFFFFF` 表示无击杀者）、2 击杀者载具、3 受害者单位号、4 击杀者单位号、10 武器。
  - `00 02 58 57` 重伤：字段 1 目标单位号、2 攻击者槽位、3 攻击者载具、4 攻击者单位号。
  - 玩家记录（可能在消息内嵌的 zstd 块里）：槽位、`70`、两字节、`30 60`、userId（u32）、4 个 0、名字。
- **服务器分段**：第 0 段带设置块；奇数段是连续的包流，偶数段是供跳转的快照，合并时跳过；最后一段带最终结果。

单位号到玩家的对应来自击杀和重伤消息里出手一方的「槽位 + 单位号」。单位号会复用：载具被击毁后，同一个号可能分给别的玩家的下一辆载具，所以每个单位号按受害时刻分成若干「命」，只在同一命里认定归属。每名玩家的第一辆载具满足「单位号 = 槽位 + 固定偏移」（空战整场都满足），没出过手的第一命据此推算。玩家载具同样来自这两类消息，服务器结果块里的出战载具会一并列出。

- **类型 2（飞机状态）**：跳过首字节后是按位写入、**高位在前**的条目列表。每条以 1 位开头：为 1 时后跟变长整数单位号（取低 11 位），为 0 时单位号是上一条加 1；`7FF` 表示列表结束。接着是「只有单位号」标志、几个标志位和计数表，然后是位置（3 个小端 float32：x、高度、z）、紧凑欧拉角，以及发动机、传感器、干扰弹、目标等可变长子表（解析时逐段跳过）。录像者自己的飞机也在其中。
- `00 02 58 73` / `00 02 58 74` 地面同步（客户端 / 服务器录像）：签名后是变长整数位长和位流体。体里是单位号范围（两个 u16）、同步时刻、序号，然后每个单位一组标志、包序号和状态体。状态体要么是完整的，要么是相对 32 槽历史里某次的增量（2 位 RLE 压缩后与基线逐字节异或）。状态体里的位置是 3 个 float32，或两个 u32 量化值（x、z 各 22 位，覆盖 ±36000 米）。服务器录像跳过了偶数分段，缺基线的增量直接丢弃。

类型 2 条目、地面同步、字段序列化和击杀字段的格式参考了 [WTACRP](https://github.com/ShioUmiusi/WTACRP)（MIT）对 wrpl-acmi 解析器的整理，本项目按格式说明自行实现。
