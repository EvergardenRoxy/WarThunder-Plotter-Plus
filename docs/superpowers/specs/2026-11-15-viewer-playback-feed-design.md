# 查看器改版：轨迹淡化、倍速播放、空战图、兵种图标、战斗播报 设计

日期：2026-11-15　　基线：`30a96d5`（0.3.2），全量测试 161 通过、2 跳过。

## 1. 目的

比赛查看页现在有四个问题：
- 一屏放不下，空间利用率低，时间轴要往下翻才能看到。
- 整场轨迹叠在一起，看不清。
- 播放只有固定的 10 倍速。
- 空战局（match/7）显示成陆战底图，而且一条轨迹都没有。

这次改版让比赛页一屏看完，轨迹只保留最近一段并逐渐变淡，可以按倍速播放，空战局能正常看。同时把已有但没显示的兵种信息画出来，并新增击杀播报的记录与显示。

目标（用户逐条确认）：

- 比赛页的 `<main>` 高度为 `calc(100vh - 顶栏高度)`，`overflow: hidden`。网格两列，右栏固定 320px。
- 左栏：画布区域占满剩余高度，播放条固定在下方。实时页没有时间轴，播放条只显示"实时"状态和当前时长。
- 右栏：纵向 flex。上面是紧凑的控件区，战斗播报 `flex: 1; overflow-y: auto`。
- 比赛标题、地图名、起止时间并入顶栏。`ⓘ` 是一个 `<details>`，展开后显示原来那些详细字段：空战地图、初始占领点、重心。去掉页面里单独的"返回"按钮。
- 顶栏所有元素垂直居中，修复截图里"比赛 实时"偏上的问题。按钮、下拉框、链接统一高度为 32px。
- 窗口宽度小于 900px 时，右栏移到画布下方，这时允许页面滚动。这是窄屏下的妥协，不算违反反目标。
- 首页：沿用新顶栏，列表样式统一，元素垂直居中。

## 6. 行为细节

### 6.1 设置与记忆
- 通用模块 `static/settings.js` 挂在 `window.Settings`，提供 `load(key, defaults)` 和 `save(key, value)`，存 JSON。读出来的对象会和默认值浅合并，缺的字段补默认值。
- 查看器使用的键是 `wtp.viewer`，内容为 `{ trail, blipSize, speed, filters }`。

### 6.2 轨迹淡化
- 档位常量为 `trailOptions: [10, 30, 60, 120, 0]`，默认 30。0 表示全部。
- 可见范围沿用 `_visibleRange`。选 0 以外的档位时，把可见段按时间平均切成 `fadeBands = 8` 段，每段的不透明度为 `段中点距窗口起点的时间 / 窗口长度`。描边和本色都乘这个值，阵营原有的 `lineAlpha` 也乘上去。
- 当前位置标记和阵亡 × 不淡化。

### 6.3 播放
- 倍速 `speed` 由滑块控制（min 5，max 40，step 1，默认 10），替代 `VIEW_STYLE.playbackSpeed`。
- 点播放时，如果时间轴已经在末尾，就从 0 开始，否则从当前位置开始。播到末尾自动暂停。拖动时间轴会暂停播放（沿用现状）。播放中调倍速立即生效。

### 6.4 空战图切换
- 服务端：
  - `map.png` 路由增加 `?kind=air`，返回 `air_map_hash` 对应的图片，没有空战图时返回 404。
  - 比赛页给画布加上 `data-has-air-map` 和 `data-default-map`。`default-map` 的规则（用户定）：比赛有空战图，且**第一次出击的载具是飞机**，取 `air`，否则取 `ground`。
  - "第一次出击"指本场按时间排序后，第一个载具名不在 `CAPTURE_DEFAULTS.placeholder_vehicles = ("", "dummy_plane")` 中的 tick。出击前，游戏会报告 `air / dummy_plane` 这个占位值，所以要排除。还没有出击（实时页刚开局）时取 `ground`。
  - 用现有数据核对：match 1～5 第一次出击是坦克，match 7 是 `f-4s`。
  - 新增函数 `db.first_sortie_army(conn, match_id, placeholders) -> str | None`。
- 查看器：
  - 原来的 `isAirMap` 改为由 `battleType === 'air' || mapKind === 'air'` 推出。
  - 载入时，同时保留原始坐标 `x, y` 和 `x_ground, y_ground`，不再在载入阶段选定显示坐标。
  - `_buildTracks` 按 `mapKind` 选显示坐标：
    - 地面图：有 `x_ground` 用它，否则用 `x`。空中视角且没有 `x_ground` 的点丢弃，地面图上的飞机也丢弃，沿用现状。
    - 空战图：只取 `is_player_air_view` 的点，用原始 `x, y`。
  - 坐标不在 [0, 1] 内的点丢弃。位置记录数仍然统计全部点。
  - `setMapKind(kind)` 先换底图，再重建轨迹、重新绘制。比赛页只在 `has-air-map` 时显示切换按钮。

### 6.5 兵种图标
- 对象的 `icon` 字段和形状的对应：

| icon | 形状 |
|---|---|
| `LightTank` | 菱形 |
| `MediumTank` | 圆形 |
| `HeavyTank` | 方形 |
| `TankDestroyer` | 上三角 |
| `SPAA`、`SAM` | 圆加十字 |
| `Wheeled` | 五边形 |
| `Fighter` | 箭头 ×1.0 |
| `Assault` | 箭头 ×1.15 |
| `Bomber` | 箭头 ×1.3 |
| `Player` | 保持现在的玩家圆点加白环 |

- 其他 icon，如 `Artillery`、`Pillbox`、`Destroyer`、`Airdefence` 和未知值：载入时丢弃，不画轨迹也不画标记（用户：暂不显示）。占领点、重生点这些 POI 不受影响。
- 箭头指向轨迹最后两点的方向，只有一个点时朝上。
- 标记的屏幕尺寸为 `blipSize × markerBase`，`markerBase = 14px`，即外接正方形的边长；玩家标记再乘 1.4。默认 0.5 时为 7px。
- 轨迹点保留 `icon`。标记用轨迹最后一点的 `icon`。
- 悬停：在画布上移动鼠标时，命中最近的当前位置标记（屏幕距离不超过标记半径 + 4px），在鼠标旁的浮层里显示 `unit.<icon>` 的译名。拖动时不显示。
- 图例：放在筛选面板底部，用内联 SVG 画同样的形状，配上译名。

### 6.6 战斗播报
- 接口格式：按社区资料，`GET /hudmsg?lastEvt=0&lastDmg=<id>` 返回 `{"events": [...], "damage": [{"id": int, "msg": str, "time": int, ...}]}`。**这个格式还没有用真实游戏数据核对过**，由用户之后测试；执行时如有差异，只需要改 `TelemetryClient.fetch_damage` 和测试样本。
- 采集：
  - `Capturer._capture_tick` 在 `map_valid` 时调用 `client.fetch_damage(tracker.damage_cursor)`，结果交给 `tracker.record_damage(now, entries)`。
  - `MatchTracker` 在每场比赛的状态里记录 `damage_cursor`（初值 0）和 `damage_primed`（初值 False）。
  - 本场第一次收到结果时只把游标推到最大 id，不入库，以跳过上一场的残留消息；之后的消息入库。
  - 接口返回 None（不可用）时跳过，不影响轨迹采集。
- 存储：新表 `events`，字段为 `id`、`match_id`、`timestamp_ms`（收到时刻相对比赛开始的毫秒数，与 tick 同一基准）、`game_id`、`msg`、`raw`（整条原始 JSON）。`delete_match` 同时删除这张表里的记录。
- 接口：`GET /api/match/<id>/events?since=<ms>` 返回 `[{ "timestamp": ms, "msg": str }]`，按时间升序。
- 显示：
  - 查看器载入位置的同时增量载入播报，实时页随轮询更新。
  - 列表显示 `timestamp <= cutoff` 的播报，最新的在最上面，每条前面带 `m:ss`。播放时随时间更新。
  - 文字用 textContent 写入。没有播报时显示"暂无播报"。
