# WT Plotter Plus 重建 Implementation Plan

> **For agentic workers:** 按 `docs/superpowers/plans/executor-prompt.md` 的规则逐个 Task 执行。每次会话只做一个 Task。步骤用 `- [ ]` 勾选跟踪。

**Goal:** 以上游代码为参考，用 Python 重建 War Thunder 比赛轨迹记录器，支持中英双语，结构符合 `AGENTS.MD`。

**Architecture:** 单个包 `wt_plotter`，分为 maps / i18n / storage / capture / web / desktop 六块。采集状态机不碰网络，靠注入的连接与取图函数工作，可离线测试。界面文字全部来自 JSON 语言文件，地图以 `map_id` 为标识、显示名放语言文件。

**Tech Stack:** Python 3.11、Flask 3、requests、click、Pillow、pystray、SQLite、原生 JS Canvas、pytest、PyInstaller。

**Spec:** `docs/superpowers/specs/2026-11-15-rebuild-design.md`（执行者必须同时阅读）

## Global Constraints

- 解释器：`py -3.11`；虚拟环境 `.venv`；一切命令用 `.venv\Scripts\python`。
- 运行依赖仅 `flask>=3.0` `requests>=2.31` `click>=8.1` `Pillow>=10.0` `pystray>=0.19.5`。禁止 `numpy`、`aiohttp`。
- `wt_plotter/` 内禁止 `except Exception`、裸 `except`、`except ...: pass`。
- `wt_plotter/` 内禁止出现字符串 `ElBartt`（`LICENSE`、README、CHANGELOG 的致谢除外）。
- 禁止用显示文字做判断；地图判断只用 `map_id`、`battle_type`、`location`。
- 注释中文且简短；标识符、日志、命令行帮助、提交信息英文。
- `reference/upstream/` 只读，不提交。
- 不 `git push`，不改动项目目录之外的任何文件，不全局安装包。
- 表结构与上游 `db.py::_create_tables` 逐字相同。
- 版本 `0.3.0`；产品名 `WT Plotter Plus`；更新仓库 `EvergardenRoxy/WarThunder-Plotter-Plus`。
- 全量测试命令：`.venv\Scripts\python -m pytest -q`，每个 Task 结束时必须全绿。

## Review Focus

以下输入最可能坑到用户，各自的测试已写入所属 Task：

1. 游戏没开、接口拒绝连接 → 不报错、不建比赛（Task 6）。
2. 配对点在某一轴上坐标全相同（方差 0）→ 坐标换算返回 `None`，不除零（Task 5）。
3. 取不到地图图片或哈希未知 → 比赛照常记录为未知地图，哈希写入缺失日志（Task 2、5）。
4. 语言文件缺键或两种语言键集不一致 → 测试失败（Task 3、7）。
5. 删除进行中的比赛 → 400 `cannot_delete_active`（Task 7）。

## 人工前置（不阻塞执行）

用户用上游程序录制真实比赛，供 Task 5 的回放测试使用。未录制时回放测试参数为空，其余照常进行；录制后重跑 `pytest tests/capture/test_replay.py` 即可。步骤见 `reference/README.md`。
